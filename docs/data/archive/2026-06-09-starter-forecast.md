# 2026년 6월 9일 선발 로테이션 예상

조회 기준: 2026-06-08 11:58 KST.

사용 데이터:

- 일정: `docs/data/2026-06-kbo-schedule.md`
- 실제 선발: `docs/data/2026-06-kbo-starters.md`
- 공식 예고 확인: KBO GameCenter `PREVIEW`

## 작업 규칙

1. 06.02~06.07 실제 선발을 `ACTUAL` 성격의 과거 기록으로 사용한다.
2. 06.09 선발은 최근 실제 선발 블록 기준의 `SYSTEM_PREDICTED`로만 기록한다.
3. KBO GameCenter `PREVIEW`에 공식 예고 선발 이름이 없으므로 `OFFICIAL_ANNOUNCED`는 아직 비워둔다.
4. 공식 예고가 게시되면 시스템 예상과 별도로 추가하고, 화면/비교에서는 공식 예고를 우선한다.
5. 경기 후에는 `Schedule.aspx`에서 정식 경기 여부를 확인한 뒤 GameCenter `REVIEW`의 `등판=선발` 행만 `ACTUAL`로 비교한다.

## 로테이션 변경 체크 위치

- KBO `Schedule.aspx`: 경기 종료, 취소, 우천취소, 예정 상태를 먼저 확인한다.
- KBO GameCenter `REVIEW`: 정식 경기로 끝난 경기의 실제 선발만 확인한다.
- KBO GameCenter `PREVIEW`: 공식 예고 선발이 게시됐는지 확인한다.
- KBO `Player/Register.aspx`: 팀별 등록/말소 상태를 확인해 선발 후보의 1군 등록 여부를 운영자 판단 자료로 쓴다.
- KBO `Player/Trade.aspx`: 부상, 재활, 이동 등 선수 변동 상세를 운영자 판단 자료로 쓴다.

MVP v1에서는 등록/말소/부상 정보가 `SYSTEM_PREDICTED`를 자동 변경하지 않는다. 변동 신호가 있으면 운영자가 `rotation_slots`나 `team_rotation_states.next_slot_no`를 보정하고, 이 문서에는 변동 체크 메모만 남긴다.

## 다음 처리

1. 06.09 공식 예고가 KBO GameCenter `PREVIEW`에 게시되면 `OFFICIAL_ANNOUNCED` 컬럼을 채운다.
2. 공식 예고와 시스템 예상이 다르면 시스템 값을 수정하지 말고 비교 상태만 `다름`으로 기록한다.
3. 06.09 경기 종료 후 `Schedule.aspx`에서 종료/취소 상태를 먼저 확인한다.
4. 종료 경기만 GameCenter `REVIEW`에서 실제 선발을 추출해 `ACTUAL` 비교표를 추가한다.
5. 임시 선발이 확인된 팀은 포인터를 자동 전진하지 말고 운영자 판단 메모를 남긴다.
