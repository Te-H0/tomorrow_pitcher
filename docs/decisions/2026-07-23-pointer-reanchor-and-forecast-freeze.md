# Pointer Re-anchor and Forecast Freeze (Model B)

## Status

Accepted

## Date

2026-07-23

## Context

`2026-05-22-manual-rotation-pointer-mvp.md`는 시스템 예상을 운영자 통제형 로테이션 포인터로 정했다. 초기 구현은 어제 실제 선발이 예측과 **정확히 일치할 때만** 포인터를 전진시키고, 불일치하면 무조건 보류(`auto-hold`)했다.

검증 운영 중 두 가지 문제가 드러났다.

1. **불일치 = 무조건 보류**는 과하다. 실제 선발이 로테이션에 이미 있는 투수인데 순서만 빗나간 경우(예: 예상 황동하, 실제 올러)에도 사람이 손대기 전까지 포인터가 멈췄다. 2026-07-23 기준 10팀 중 7팀이 이 문제로 `auto-hold` 상태였고, 그중 4팀(KIA·한화·SSG·키움)은 단순히 "아는 투수가 순서만 다르게 나온" 경우였다.

2. **예측 동결 시점이 "처음 쓸 때"**여서, 포인터를 고쳐도 이미 생성된 미래 예측(D-3까지)이 갱신되지 않았다. 홀드를 교정해도 앞으로 3일치 예측이 틀린 값으로 남았다.

또한 포인터가 이동하면 과거 예측의 비교(`일치`/`불일치`) 컬럼이 새 포인터 기준으로 재계산되어 적중률 기록이 오염되는 버그가 있었다.

## Decision

### 1. 포인터 재정렬(re-anchor)

포인터는 **"가장 최근에 나온, 로테이션에 아는 투수"를 따라간다.**

어제 실제 선발 P에 대해:

- P가 슬롯 목록에 있으면(적중이든 순서 빗나감이든) **그 투수 슬롯 기준으로 재정렬**한다. 포인터 = P 슬롯 다음의 예측 가능 슬롯.
  - P == 예측이면 `auto` (정상 전진).
  - P != 예측이지만 아는 투수면 `auto-reanchor` (자동 교정).
- P가 슬롯에 없으면(콜업·땜빵) **보류**(`auto-hold`)하고 사람 확인을 기다린다.
- 취소 경기는 보류.

핵심 효과: 모르는 투수가 잠깐 나온 뒤 다시 아는 로테이션 투수가 등판하면, 매일 잡이 그 순간 자동으로 포인터를 복구한다. 사람 개입은 "모르는 투수가 로테이션에 눌러앉을 때"만 필요하다(`slots.md`에 반영하면 그때부터 다시 아는 투수로 처리).

### 2. 예측 동결 시점(Model B)

예측 immutability를 "처음 쓸 때 동결" → **"공식 예고 확인 시 동결"**로 바꾼다.

- 공식 예고 전(비교=`예고대기`)까지는 매 실행마다 현재 포인터로 갱신한다. → 포인터 재정렬/전진이 미래 예측에 즉시 반영된다.
- 공식 예고 확인 시점(비교=`일치`/`불일치`)에 그 값으로 동결한다. → 이후 포인터가 움직여도 그 행을 건드리지 않아 적중률 기록이 보존된다.
- 비교는 저장된 예측 기준으로 계산해 포인터 이동에 오염되지 않게 한다.

적중률은 "공식 예고 직전 시점의 예측"으로 측정된다.

## Non-Goals

- 뉴스/AI가 포인터나 예측을 자동 변경하는 것(기존 결정 유지).
- 로테이션에 없는 새 투수를 코드가 자동으로 슬롯에 편입하는 것.
- 예측 값을 사후에 손보는 것(동결 이후는 불변).

## Data Implications

- `rotation/pointers.md`의 `갱신 주체`에 `auto-reanchor` 상태 추가.
- `starters/predicted/YYYY-MM.md`의 예고대기 행은 갱신 가능, 일치/불일치 행은 동결.

## Consequences

- 평시 운영 부담이 "매일 10팀 확인" → "모르는 투수 나온 날만 개입"으로 줄어든다.
- 미래 예측이 최신 로테이션 상태를 반영하므로 사용자에게 보여줄 값이 최신이다.
- 적중률 기록은 공식 예고 시점 스냅샷으로 정직하게 남는다.
- 구현: `scripts/generate-starter-forecast.mjs` (커밋 098948a re-anchor, df1aca7 Model B). 실측 검증: KIA(올러→슬롯2 재정렬), 삼성(김백산→보류), 미래 07.24~26 재정렬 반영, 과거 07.23 이하 동결 보존.
