# Derived Rotation from Observations (순서 저장 폐기)

## Status

Accepted

## Date

2026-08-14

## Context

8/5~8/9 연속 우천 취소 후 8/11 재개 구간에서 예측이 붕괴했다(8/11~14 예고 대비 25%, 8/13은 0%). 원인은 수동 관리 `slots.md`가 재개 후 로테이션 재편(KIA 네일↔시라카와 교체, KT 대니엘 신규, 키움 알칸타라 복귀·안우진 말소, LG 웰스 말소 등)을 따라가지 못한 것. 근본 문제는 "슬롯 순서"라는 상태를 사람이 저장·관리하는 구조 자체였다 — 갱신 주기의 문제가 아니라 모델 표현의 문제.

백테스트(7/18~8/13, `scripts/backtest-restday-forecast.mjs`, 생성 시점 09:00 KST 재현, lead별 분리)로 검증했다. 파생 모델 측은 별도 재현 코드가 아니라 **배포되는 `deriveRotation()`을 as-of 옵션(actualThrough/knownBy)으로 직접 호출**해 측정한다 — 상수·규칙이 바뀌면 백테스트도 자동으로 같은 것을 잰다.

| lead | 슬롯 모델(실운영 git 스냅샷) | 관측 파생 모델(배포 경로) |
|---|---|---|
| D+1 | 21/154 (13.6%) | 88/154 (**57.1%**) |
| D+2 | 16/144 (11.1%) | 72/144 (**50.0%**) |
| D+3 | 11/144 (7.6%) | 60/144 (**41.7%**) |

파생 모델이 전 구간 압승(상세: `docs/progress/2026-08-14-restday-backtest.md`). 단 재개 첫날(8/11~13)은 두 모델 모두 약하다 — 재배치는 관측만으로 못 맞히며, 이 구간의 정답은 감독 브리핑 기사에 있다(뉴스 claims 파이프라인, 백로그).

## Decision

### 1. 로테이션을 저장하지 않고 관측에서 매 실행 파생한다

`scripts/lib/rotation.mjs` `deriveRotation()`:

- 후보 풀: 최근 20일 실제 선발 등판자 + 예고에 뜬 투수(신규 외국인·콜업 즉시 편입, 의사 등판일 = 예고 경기일-5).
- 순서: 마지막 등판일 오름차순 = 가장 오래 쉰 투수가 슬롯 1(다음 차례). 휴식일 기반 파생 순서.
- 자동 제외: 마지막 등판 14일 초과(이탈 추정, 단 최근 예고에 뜨면 유지), 말소 후 재등록·재예고 없는 투수(10일 규정 커버 — 예: 하영민 8/6 말소).
- TEMPORARY: 윈도 내 1회 이하 등판(스팟/신규 미검증). 예측 포함, 표기만.
- 예고 앵커 일자별 시뮬레이션·동결(Model B)·취소 보정은 기존(2026-08-09 결정) 유지.

### 2. slots.md / pointers.md는 파생 아티팩트로 강등

둘 다 forecast 실행 시 자동 생성되는 사람 확인용 스냅샷이며 편집하지 않는다. 포인터 전진/재정렬 로직(auto/auto-reanchor/auto-hold)은 파생에 흡수되어 삭제됐다 — 어제 결과 반영이 파생에 자동 포함되므로 별도 상태 기계가 필요 없다.

### 3. 사람 보정은 rotation/overrides.md 단일 진입점

`| 팀 | 투수 | 처리(제외/포함) | 기준일 | 메모 |`. 부상 이탈은 "제외", 복귀 예정은 "포함". 해소되면 행 삭제. 향후 뉴스 claims 확인 큐의 승인 결과도 이 파일로 합류한다.

보정이 조용히 무시되지 않도록: 팀명은 표준 표기(kbo.mjs `TEAM_NAME_BY_CODE`)로 검증하고, 기준일은 YYYYMMDD 8자리만 허용하며, "제외" 대상이 풀에 없으면 경고를 낸다. "포함"은 upsert — 풀에 이미 있는 투수도 기준일·override 플래그를 덮어써 장기 미등판 필터에서 구제할 수 있다.

### 4. 재개 첫날 저신뢰 표기

직전 3경기+ 연속 취소 후 첫 경기의 예측은 근거 슬롯에 `저신뢰(재개 첫날)`를 표기한다. 재배치 가능성 구간을 정직하게 표시(적중률 집계 방식은 불변).

### 5. 운영 안전망

- 3개 워크플로에 실패 시 GitHub 이슈 자동 생성(동일 제목 열린 이슈엔 코멘트) 추가.
- 등록/말소 수집: 경기 없는 월요일은 접수 마감이 16:30이므로 15시 → 18시 회차로 이동.
- 파생 건전성 가드: 수집기 장애로 풀이 빈약하면(3인 미만 팀 3개+ 또는 팀 8개 미만) 예측·아티팩트를 생성하지 않고 실패시킨다 — 빈약한 예측이 동결되면 적중률 기록이 영구 오염되기 때문.
- 저녁 회차(sync-postgame)의 파생은 당일 실제 선발까지 반영한다(기본 actualThrough=asOf) — 방금 던진 투수가 "다음 차례"로 남는 것을 방지.

## Consequences

- 낡은 슬롯으로 인한 예측 붕괴 유형이 구조적으로 사라진다(자기 치유: 실제 등판이 기록되는 즉시 파생이 교정됨).
- 재개 첫날·감독 재량 재배치는 여전히 못 맞힌다. 대응은 저신뢰 표기(적용됨)와 뉴스 claims 파이프라인(백로그).
- 6인 로테이션·불규칙 순환도 순서가 관측에서 나오므로 자연 대응된다.
- 기존 `auto-hold` 기반 운영 문서(2026-08-09 결정의 일부 서술)는 이 결정으로 대체된다.
