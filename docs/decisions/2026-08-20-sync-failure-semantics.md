# 수집 워크플로 실패 판정 재정의 (오탐 제거 + 조용한 고장 감지)

## Status

Accepted

## Date

2026-08-20

## Context

자동 수집 3종(sync-daily / sync-preview / sync-postgame) 중 `sync-preview`가 상시 실패 상태였다. 최근 60런 기준 실패 10 · 취소 2 · 성공 48이고, 실패는 전부 sync-preview에 몰려 있었다.

두 가지 원인이 겹쳐 있었다.

**1) 정상 상황을 실패로 올렸다.** `extract-kbo-preview.mjs`는 예고 수집이 0건이면 무조건 `exit 1`이었다. 그런데 sync-preview는 KST 09/12/15·18/21/23시로 하루 6회 돌고, KBO 공식 예고는 전날 경기 종료 후 나온다. 즉 이른 회차는 "아직 예고 없음"이 **정상**인데도 매번 실패로 기록됐다. 실제 실패 시각도 UTC 12:2x~12:5x(KST 21시), 14:16(23시), 00:55(09시)에 몰려 예고 발표 전 회차와 정확히 일치했다. 경기가 아예 없는 월요일(예: 08.17)도 같은 이유로 실패했다.

코드 주석은 *"대상 날짜에 경기가 존재했는지로 정상/실패를 가른다"*고 서술했지만 실제 구현은 그 판정을 하지 않았다 — 주석과 구현의 괴리.

그 결과 2026-08-14 결정 §5로 도입한 실패 알림 이슈(#1)에 오탐 코멘트가 6개 쌓였고, 알림이 신호 역할을 잃었다.

**2) 타임아웃이 없었다.** 08-18 두 런이 각각 6시간 0분 / 3시간 5분 돌다 취소됐다. 로그 말미의 `Terminate orphan process: npm exec playwright install chromium --with-deps` 로 보아 브라우저 설치가 매달린 것이다. 세 워크플로 모두 `timeout-minutes`가 없어 GitHub 기본 6시간까지 방치됐고, 셋이 `concurrency: data-sync`를 `cancel-in-progress: false`로 공유하므로 **좀비 런 하나가 뒤따르는 모든 수집을 큐에서 막았다**(08-18 03:39 런이 3시간 걸린 이유).

## Options

- A. 워크플로에서 예고 미발표 회차를 `continue-on-error`로 덮는다 — 실패는 가려지지만 진짜 고장도 같이 가려진다.
- B. 예고가 나올 만한 시각의 회차만 엄격 판정한다 — 시간 기준이 자의적이고 취소·월요일 예외가 계속 늘어난다.
- C. **수집한 데이터 자체로 판정한다** — GameCenter에서 경기를 읽었는지, 일정상 경기가 편성됐는지로 "경기 없음 / 예고 전 / 진짜 고장"을 가른다. (채택)

## Decision

### 1. 예고 0건의 판정을 데이터로 가른다

`extract-kbo-preview.mjs`는 이미 `readGameConts()`로 그날 경기 목록 전체를 읽고 있다(예고 여부와 무관). 여기에 일정 데이터를 대조해 세 갈래로 나눈다.

| 상황 | 판정 |
|---|---|
| GameCenter에서 경기를 읽었고 예고만 0건 | 정상 no-op (exit 0) — 예고 발표 전 |
| GameCenter 경기 0건이고 일정에도 경기 없음 | 정상 no-op (exit 0) — 경기 없는 날 |
| GameCenter 경기 0건인데 **일정에는 경기 편성** | **실패 (exit 1)** — 페이지 구조/로딩 고장 |

일정 대조는 `docs/data/schedule/YYYY-MM.md`를 읽는다. 월 경계로 다음 달 일정 파일이 아직 없으면 판단 불가로 보고 정상 처리한다 — 오탐 실패가 알림을 죽인다는 것이 이번 사건의 교훈이므로, 애매하면 통과시키고 아래 2의 사후 검증에 맡긴다.

### 2. 조용한 고장은 사후 검증으로 잡는다

1의 대가로 새 사각지대가 생긴다: KBO가 `start_ck` 속성이나 `li.game-cont` 구조를 바꾸면 경기는 읽히지만 예고가 항상 0건이 되어 **영원히 조용히 통과**한다.

이를 `scripts/check-preview-health.mjs`로 막는다. 근거는 단순하다 — **이미 '종료'된 경기는 예고가 반드시 발표됐어야 한다.** 어제 날짜의 일정에서 상태가 `종료`이고 gameId가 찍힌 경기를 모아, 그 gameId가 공식 예고 표에 없으면 수집이 깨진 것으로 보고 실패시킨다. 취소·예정·미정 경기는 예고가 없을 수 있어 판정 근거에서 제외한다.

네트워크가 필요 없는 로컬 md 대조라서 sync-daily(KST 08:00) 마지막 수집 스텝 뒤에 붙였다. 운영 개시 후 구간(07-19~08-19)에 대해 오탐 0건이고, 수집 이전 구간(07-17 등)은 정확히 누락으로 잡는 것을 확인했다.

### 3. 타임아웃

세 워크플로 모두 잡에 `timeout-minutes: 20`, `playwright install` 스텝에 `timeout-minutes: 10`. 정상 런은 1~3분이므로 여유가 충분하다. 좀비 런이 `data-sync` 큐를 막는 경로가 닫힌다.

### 4. 복구 시 실패 이슈 자동 종료

실패 이슈는 열리기만 하고 닫히지 않아 "열린 이슈 = 지금 고장 중"이라는 의미가 유지되지 않았다. 세 워크플로에 `if: success()` 스텝을 추가해 같은 제목의 열린 이슈가 있으면 복구 런 링크와 함께 닫는다. 지속 고장이면 다음 실패에서 다시 열리므로 상태가 자동으로 수렴한다.

## Consequences

- sync-preview의 상시 실패가 사라지고, 실패 알림이 다시 신호로 기능한다.
- 진짜 고장의 감지 경로가 둘로 늘었다: 즉시 감지(1, 페이지에서 경기를 못 읽음)와 하루 지연 감지(2, 종료 경기에 예고 없음). 후자는 최대 하루 늦지만 셀렉터 변경 같은 조용한 고장을 잡는 유일한 그물이다.
- 판정이 `docs/data/schedule/`에 의존하게 됐다. 일정 수집(sync-daily)이 깨지면 preview 판정도 함께 둔해진다 — 다만 그 경우 sync-daily 자체가 실패해 알림이 뜬다.
- 2026-08-14 결정 §5의 "실패 시 이슈 자동 생성"은 유지하되, 종료 자동화(4)가 더해져 대체된다.
